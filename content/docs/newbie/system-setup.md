{{< heading level="1" id="page-heading" >}} Перше налаштування користувацької системи {{< /heading >}}

Незалежно від обраного дистрибутиву, існує ряд речей, які варто використати на більшості існуючих систем. Ці речі або впливають на продуктивність, або надають стабільність у випадках користувацьких систем, однак не включені через універсальність ядра Linux.

# Додаткові пакети

У кожної системи існує додатковий репозиторій, в якому існують пакети, які не були включені через ряд причин(ліцензії, підтримку спільності, нестабільність тощо). Із пакету вони існують виключно в частині деривативів, тому у разі встановлення дистрибутиву, який їх не містить, їх варто мати для певних кроків.

> Ставтесь до користувацьких репозиторіїв з увагою. Користувацькі пакети можуть містити фрагменти шкідливого коду

## Ubuntu PPA

В Ubuntu існує користувацький репозиторій PPA, в якому пакети прив'язані до користувачів. У порівнянні з іншими дистрибутивами проглядається значний мінус - для кожного пакету(або набору пакетів) потрібно додавати кожне посилання окремо.

```bash
sudo apt-add-repository ppa:author/package
sudo apt update
sudo apt install package
```

## RPM Fusion

Fedora має декілька рівнів в плані реалізації репозиторіїв. Більш офіційним є RPM Fusion - репозиторій, який включає в себе більшість пакетів, які мали б бути у офіційному репозиторії, однак не включені через вже описаний ряд причин. На відміну від користувацького, цей репозиторій знаходиться на серверах Fedora.

```bash
# Fedora
sudo dnf install https://mirrors.rpmfusion.org/free/fedora/rpmfusion-free-release-$(rpm -E %fedora).noarch.rpm https://mirrors.rpmfusion.org/nonfree/fedora/rpmfusion-nonfree-release-$(rpm -E %fedora).noarch.rpm

# Все, що не Fedora (RHEL, Rocky, Alma)
sudo dnf install --nogpgcheck https://mirrors.rpmfusion.org/free/el/rpmfusion-free-release-$(rpm -E %rhel).noarch.rpm https://mirrors.rpmfusion.org/nonfree/el/rpmfusion-nonfree-release-$(rpm -E %rhel).noarch.rpm
```

## Fedora COPR

Це користувацький репозиторій Fedora. Туди потрапляє все, що не потрапляє у RPM та RPM Fusion.

```bash
sudo dnf install "dnf-coommand(copr)"
sudo dnf copr enable author/package
sudo dnf install package
```

## AUR

Arch User Repository - головне джерело пакетів, які не потрапили в основний репозиторій. Плюс - деякі програми існують на AUR, бо розробник не створив Tarball(архів зі скомпільованим кодом). Мінус - нещодавній експлойт забутих та мігрованих пакетів трошки підкосив довіру користувачів

Значний плюс - AUR помічники(програми, що працюють з цим репозиторієм) працюють одночасно з основним та з користувацьким репозиторієм, тобто замість звичного `sudo pacman` можна писати `yay` або `paru`, а написання цієї команди без параметрів одразу запустить оновлення системи.

```bash
sudo pacman -S git base-devel fakeroot curl
git clone https://aur.archlinux.org/yay.git
cd yay
makepkg -si
```

# ZRAM

Ця технологія заміняє звичне перенесення даних оперативної пам'яті на носій даних. 
Звична схема переповнення ОЗП виглядає наступним чином:
```
1. Оперативна пам'ять приймає в себе дані для роботи
2. Пам'ять переповнюється
3. Надлишок йде у файл, що зберігається на SSD/HDD 
4. Коли закінчується весь об'єм і ОЗП, і виділеного об'єму надлишкової пам'яті, система починає паніку і вбиває деякі процеси або перезапускається
```

З технологією ZRAM схема трошки змінюється:
```
Система резервує частину оперативки -> Оперативна пам'ять приймає в себе дані для роботи -> У разі переповнення стискає частину надлишкових даних та передає у даний резерв -> Коли закінчується весь об'єм і ОЗП, і виділеного об'єму надлишкової пам'яті, система починає паніку і вбиває деякі процеси або перезапускається
```

Різниця полягає у цьому проміжковому етапі - замість перенесення даних на постійну пам'ять, дані стискаються та зберігаються у окремому блоці оперативної пам'яті.

> Чому це вигідніше?

Головна відповідь - використання оперативної пам'яті.

| Носій | Швидкість | Ресурс перезапису |
| :---- | ----- | -------- |
| RAM | Дуже швидкий носій | Ресурс найбільший, бо це не постійний носій |
| SSD | Менш швидкий, але швидший за жорсткий диск | Ресурс запису доволі обмежений, порівняно з HDD значно менший |
| HDD | Найповільніший з трьох | Ресурс більший за SSD, бо запис фізичний, а не електричний, однак все ще обмежений |

Що ми маємо в результаті? SSD швидкий, однак не любить частих перезаписів. HDD вирішує проблему частих перезаписів, однак ціною неймовірно нижчої швидкості. Якщо ми обираємо стискання частини даних в саму оперативну пам'ять, маємо win-win - і диск не зношується великими перезаписами, і швидкість цих перезаписів не так страждає.
Мінуси? Треба трошки процесора, бо стискання даних - це великі розрахункові операції, які працюють лише за рахунок процесора. І не буде гібернації, тобто зберегти стан роботи для подальшого увімкнення не вдасться (воно й доволі зрозуміло, бо замість постійної пам'яті, використовується лише енергозалежна)

# Pipewire Fix

Стокова конфігурація аудіосистеми має цікаву фішку. Заради енергоефективності, у разі відсутності будь-якого аудіопотоку, канал звукового пристрою вимикається. Чи дійсно впиливає це на енергоефективність? Важко сказати. Чи створює це незручність? Так, бо щоб увімкнути назад цей канал, системі треба кілька секунд і... Так, поки у відео пройшла, ймовірно, ціла фраза, ви нічого не почуєте.

Для цього варто відредагувати файл конфігурації менеджера звукової системи PipeWire.
```bash
sudo micro /usr/share/wireplumber/wireplumber.conf
```

Після цього потрібно знайти ось такий сегмент:

```
{
  name = node/suspend-node.lua, type = script/lua
  provides = hooks.node.suspend
}
```
і розставити на початку кожного рядка #
```
# {
#   name = node/suspend-node.lua, type = script/lua
#   provides = hooks.node.suspend
# }
```

Далі треба знайти такий же текст, як і в рядку `provides =`, тобто `hooks.node.suspend` і перед ним поставити решітку. Блок після цього виглядатиме схожим на:
```
wants = [ #hooks.node.suspend
          hooks.stream.state
          hooks.filter.graph ]
```

Після цього, менеджер треба перезавантажити командою `systemctl --user restart wireplumber.service` і з цього моменту канал не має вимикатись

> Окрема нотатка: це в тому числі зупинить вимикання Bluetooth навушників, що може впливати на їх енергоефективність. Тому ця функція буде корисною не для всіх.

# Драйвер NVIDIA {#nvidia}

Так склалось, що не всі дистрибутиви обдаровані коректним драйвером для відеокарт NVIDIA. Чому?
Причини дві - старі відеокарти, які краще працюють зі старим драйвером(бо новий їх не підтримує) і універсальність дистрибутиву.

Для перевірки, чи встановлено коректний драйвер із коробки, варто перевірити дані PCI-пристроїв.
```bash
lspci -nnk | grep -A 3 VGA
```

Якщо система каже `Kernel driver in use: nouveau`, то це легасі драйвер, який не підтримує більшість сучасних функцій. Якщо написано `nvidia`, то чіпати не треба, все добре.

Фікс:

> Для Fedora треба мати ввімкнений [RPM Fusion](#rpm-fusion)

```bash
# Debian/Ubuntu
sudo apt install nvidia-open

# Fedora 
sudo dnf install akmod-nvidia-open

# Arch (стандартне ядро)
sudo pacman -S nvidia-open

# Arch (кастомне ядро)
sudo pacman -S nvidia-open-dkms

# Незалежно від системи після встановлення
nvidia-smi

# Якщо команда не виконується
lspci -nnk | grep -A 3 VGA
```
